<objective>
Implement Phase 12: Lead Identification Dashboard. Add a "Leads" page to the existing
Streamlit multi-page app that surfaces ranked lead candidates with rule + ML score,
behavioral signals, and which scoring rules fired per session.

Deliverables:
1. dashboard/heatmap_queries.py — build_lead_candidates_query() + fetch_lead_candidates()
2. dashboard/pages/leads.py — full Streamlit page
</objective>

<context>
The existing dashboard (dashboard/app.py) is a single-page app. Streamlit auto-discovers
pages placed in dashboard/pages/ — no change to app.py is required. The "Leads" entry
appears automatically in the sidebar navigation.

Data sources:
  analytics.lead_scores_rule_based — always available (Phase 10 view)
  analytics.lead_scores_ml FINAL  — optional; may be empty before score_sessions.py runs
  analytics.session_features       — always available (Phase 9 view)

The query LEFT JOINs lead_scores_ml so the page is fully functional even without ML scores.
When ML scores are absent, a warning banner is shown and leads are ranked by rule score.

Established dashboard conventions (must be followed):
  - All SQL in heatmap_queries.py, not inline in the page
  - Only aggregate/derived dataframes in Streamlit — no raw event rows
  - Parameterized queries only (clickhouse-connect %(name)s format)
  - @st.cache_resource for the ClickHouse client connection
</context>

<constraints>
- Do not modify dashboard/app.py
- Do not add raw event rows to any dataframe returned from heatmap_queries
- ML absence must never raise an error — LEFT JOIN + .notna() guard only
- Limit is capped server-side at 5000 to protect ClickHouse from unbounded scans
</constraints>
